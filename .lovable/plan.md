# X Direct Publishing & Scheduling — Deep Implementation Plan

## Executive Summary
Add first-class X (Twitter) direct posting and scheduling to PostSpark, so users can publish text, images, and videos generated by Repurpose, Image Studio, Thumbnail, Stock, or uploaded from device. This turns PostSpark from a content generator into a full social-media command center for X.

Scope: OAuth connection, composer, media upload, post/schedule, calendar queue, analytics, webhook, and cost-aware thread optimization.

----

## 1. X API Requirements & Billing Strategy

### X API endpoints we will use
| Feature | X API endpoint | Notes |
|---|---|---|
| OAuth 2.0 login | `https://twitter.com/i/oauth2/authorize` + token endpoint | PKCE, scopes `tweet.read users.read tweet.write offline.access media.write` |
| Media upload | `POST https://api.x.com/2/media/upload` (INIT/APPEND/FINALIZE) | Required for images/video attached to posts. |
| Publish post | `POST https://api.x.com/2/tweets` | Attach up to 4 images or 1 video via `media.media_ids`. |
| Delete post | `DELETE /2/tweets/:id` | For scheduled posts still pending or failed retry. |
| Revoke notification | webhook | Handle `user.revoke` to disconnect account. |

### API access level
Posting requires **X API Basic tier or higher** (write access). The free tier is read-only. The plan assumes the workspace enables write access.

### Unit economics & profit protection
- Standard text/media post: **$0.015** (per 2026 Pay-Per-Use model).
- Post containing a URL: **$0.20**.
- We will implement a **link-in-reply strategy**: first tweet = hook + media (low cost), reply tweet = link (high cost). UI will warn users when URLs are detected and offer an auto-thread mode that splits the link out.
- Per-user daily throttle + per-post budget alerts in settings.

### Credentials we need
Two possible paths. The plan will implement **Path A (custom OAuth)** unless the Lovable X connector proves to support posting.

| Path | What we need | Where it lives |
|---|---|---|
| A — Custom OAuth 2.0 (recommended) | `X_CLIENT_ID`, `X_CLIENT_SECRET` | User's X Developer App; stored via `add_secret` tool. |
| B — Lovable X connector | Existing `x` connector via gateway | Reuse if gateway supports write scopes; verify during Phase 1. |

Decision gate: in Phase 1 we will probe the Lovable X connector (`standard_connectors--get_connection_configuration`) after connecting it. If it only exposes read endpoints, we switch to Path A and request the user's X Developer credentials.

Already exists. Add/update columns for X:

```sql
ALTER TABLE public.social_accounts
  ADD COLUMN IF NOT EXISTS platform_user_id TEXT,
  ADD COLUMN IF NOT EXISTS platform_username TEXT,
  ADD COLUMN IF NOT EXISTS access_token TEXT,
  ADD COLUMN IF NOT EXISTS refresh_token TEXT,
  ADD COLUMN IF NOT EXISTS token_expires_at TIMESTAMPTZ,
  ADD COLUMN IF NOT EXISTS scopes TEXT,
  ADD COLUMN IF NOT EXISTS metadata JSONB DEFAULT '{}'::jsonb;
```

(These may already exist for TikTok/LinkedIn; confirm before adding.)

### `scheduled_posts` table
Already exists and supports `platform`, `media_url`, `media_type`, `social_account_id`, `status`, `publish_error`, `platform_post_id`. No new columns required, but we will standardize `platform='twitter'` for X.

Optional additions for richer X support:
- `media_count` (integer) — number of X media IDs attached.
- `media_storage_paths` (jsonb) — PostSpark storage paths for re-upload on retry.
- `thread_parent_id` (uuid) — link reply tweets to the first tweet in a thread.

### New `x_usage_log` table (optional, recommended for cost control)
```sql
CREATE TABLE public.x_usage_log (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  scheduled_post_id UUID REFERENCES public.scheduled_posts(id) ON DELETE SET NULL,
  action TEXT NOT NULL, -- 'media_upload', 'tweet_post', 'thread_post'
  cost_usd NUMERIC(10,4),
  x_request_id TEXT,
  created_at TIMESTAMPTZ DEFAULT now()
);
GRANT SELECT, INSERT ON public.x_usage_log TO authenticated;
GRANT ALL ON public.x_usage_log TO service_role;
ALTER TABLE public.x_usage_log ENABLE ROW LEVEL SECURITY;
CREATE POLICY "Users see own X usage" ON public.x_usage_log FOR SELECT USING (auth.uid() = user_id);
CREATE POLICY "Users insert own X usage" ON public.x_usage_log FOR INSERT WITH CHECK (auth.uid() = user_id);
```

### pg_cron job
```sql
SELECT cron.schedule('publish-x-queue', '* * * * *', $$
  SELECT net.http_post(
    url:='https://postspark.co/api/public/cron/publish-queue',
    headers:='{"Content-Type":"application/json","Authorization":"Bearer <CRON_SECRET>"}'::jsonb,
    body:='{}'::jsonb
  );
$$);
```
Runs every minute.

## 4. Backend Server Functions

All new functions live in `src/lib/socialPublish.functions.ts` or a new `src/lib/xPublish.functions.ts`.

### Authentication
- `getXAuthUrl()` — returns OAuth authorize URL with PKCE + signed state.
- `exchangeXCode(code, state)` — called by callback route. Fetches tokens, user info, upserts `social_accounts` row.
- `refreshXToken(userId)` — refreshes access token using `refresh_token`.
- `disconnectX(userId)` — deletes `social_accounts` row for platform `twitter`.
- `getXConnection(userId)` — returns `{ connected, username, avatar, expiresAt }`.

### Media
- `uploadMediaToX(userId, fileUrl, mimeType)` — downloads from PostSpark storage (or accepts public URL), performs INIT/APPEND/FINALIZE, polls `processing_info` for video, returns `media_id_string`.
- Supports images (PNG/JPG/GIF) up to 5 MB, video up to 512 MB / 2:20:20.

### Publishing
- `publishToX({ userId, text, mediaUrls, mediaType, inReplyToTweetId })` — uploads media, posts tweet, logs cost, returns `{ tweetId, error }`.
- `scheduleXPost({ userId, text, mediaUrls, mediaType, scheduledFor, repurposeJobId })` — inserts `scheduled_posts` row with status `scheduled`.
- `editScheduledXPost(id, userId, updates)` — updates pending post.
- `deleteScheduledXPost(id, userId)` — deletes pending row.
- `cancelPublishedXPost(userId, tweetId)` — calls DELETE /2/tweets when possible.

### Threading / link strategy
- `detectUrls(text)` — returns boolean.
- `buildThread(text, link)` — splits content so first tweet has media + hook, reply tweet has the link.

### Cron dispatcher
- `processPublishQueue()` — server route handler that queries `scheduled_posts` where `status='scheduled' AND scheduled_for <= now()`, locks rows with `FOR UPDATE SKIP LOCKED`, calls `publishToX`, updates status to `published` or `failed` with `publish_error`.

### Webhook
- `handleXWebhook(body, signature)` — verifies HMAC-SHA256 from `X_CLIENT_SECRET` or `X_WEBHOOK_SECRET`; on `user.revoke`, disconnects the account; always returns `200 { code: 0 }`.

## 7. Security & Permissions

- X tokens stored encrypted in `social_accounts` via existing service-role writes; never returned to client.
- OAuth state signed with HMAC-SHA256 (reuse existing `signState`/`verifyOAuthState` helpers).
- PKCE code challenge for X OAuth 2.0.
- Webhook signature verified with HMAC-SHA256.
- Cron endpoint protected by `CRON_SECRET`.
- Media download from storage verifies path starts with `userId/`.
- All publishing functions use `requireSupabaseAuth` middleware.
- Rate limiting: per-user 50 posts/hour to protect X API limits and billing.
